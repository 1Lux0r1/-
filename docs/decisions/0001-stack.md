# 0001. Стек платформы
Статус: принято
Дата: 2026-11-17 · Автор: фундамент

## Контекст
Нужна обучающая платформа на телефон (iOS, Android) и веб, в которую загружаются курсы; первый курс — школа «Путь к Senior PM». Владелец не разработчик, работу ведут несколько ИИ-агентов параллельно. Нужен ИИ-наставник (проверка, подсказки, роль заказчика), ключ ИИ нельзя отдавать в клиент. Пользователь на старте один.

## Решение
- TypeScript strict во всех слоях, монорепо pnpm.
- Приложение: Expo + Expo Router + React Native Web (одна кодовая база на три платформы), NativeWind, TanStack Query.
- Бэкенд: Supabase (Postgres, Auth, Storage, Edge Functions на Deno), RLS на всех таблицах.
- ИИ: Claude API через `@anthropic-ai/sdk` только из Edge Functions; модель `claude-opus-5-5` по умолчанию (переменная `MENTOR_MODEL`).
- Контент курсов: папка YAML + Markdown, схема zod в `packages/course-schema`.
- Бизнес-правила: чистые функции в `packages/core`, общие для клиента и сервера; сервер авторитетен.

Рассмотренные альтернативы:
- Flutter: хорош для мобильных, но второй язык (Dart) и слабее веб; агентам и экосистеме zod/TS проще с одним TypeScript.
- Next.js (веб) + отдельное мобильное приложение: две кодовые базы — вдвое больше работы и рассинхрона.
- PWA без нативного приложения: дешевле, но хуже на iOS (уведомления, установка). Остаётся запасным путём: веб-сборка Expo и есть PWA.
- Свой сервер (Node/NestJS) вместо Supabase: больше кода и администрирования без выигрыша для одного-нескольких пользователей.
- Firebase: NoSQL хуже ложится на реляционную модель прогресса и правил; Postgres + RLS прозрачнее.

## Последствия
- Версии библиотек (Expo SDK, supabase-js, @anthropic-ai/sdk, zod) фиксирует «Фундамент» при создании репозитория и дописывает сюда.
- iOS-сборка требует аккаунта Apple Developer (решение владельца).
- Стоимость: Supabase бесплатный тариф на старте; Claude API оплачивается по использованию (оценка в docs/OWNER-DECISIONS.md).
